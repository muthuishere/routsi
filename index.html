Not another gateway

Gateways swap providers. routsi swaps answerers.

LiteLLM and OpenRouter route between providers serving the same model. routsi routes between fundamentally different things — a $0.02 model and a full autonomous agent — and picks per task.

🔀 Typical LLM gateway

  • –Load-balances one model across providers
  • –Fallback when a provider is down
  • –You still decide which model, every call
  • –A hosted platform you depend on

◆ Agent spotlight

Route to a real agent, not just a model.

Most routers stop at models. routsi treats any agent — Devin, Codex, Copilot, Claude Code — as a first-class model (e.g. devin/claude-opus-4.8), so a hard task gets handed to a full autonomous agent while the whole thing still speaks OpenAI.

The trick is conversation identity: give routsi an X-Conversation-Id and it maps that thread to a real agent session — resuming it on every later turn, so the agent keeps its context across calls.

  1. Name any agent as a model — "model":"devin/claude-opus-4.8" (or codex/…, copilot/…, claude/…). routsi runs that agent's CLI.
  2. Pass X-Conversation-Id once. The first turn opens a real agent session; routsi captures its id.
  3. Every next turn resumes that session — the agent remembers the plan, the repo, the decisions.
  4. Or let routing decide: set a dynamic group's high: devin/claude-opus-4.8 — cheap questions hit a small model, hard ones escalate straight to an agent.
hard task → real agent session, OpenAI wire
curl localhost:8080/v1/chat/completions \
  -H 'content-type: application/json' \
  -H 'X-Conversation-Id: refactor-thread-1' \
  -d '{"model":"devin/claude-opus-4.8",
       "messages":[{"role":"user","content":"draft a refactor plan"}]}'

# next turn, same header → the agent RESUMES the session, keeps its context
# response header:  X-Selected-Model: devin/claude-opus-4.8
What's in the box

Batteries included, zero platform.

Everything runs in one binary you own — routing, memory, workers, dashboard, auth.

🎯

Task-aware routing

auto classifies each question and picks a tier. A concrete model name is a hard bypass. The pick is disclosed in X-Selected-Model.

🧠

Sticky conversations

Pinned by conversation id, escalate-only — a thread never silently downgrades to a weaker model mid-conversation.

🤖

Agents as models

Devin, Codex, Copilot, Claude Code — each exposed as <agent>/<model> in /v1/models, conversation-capable.

🔌

Pull-workers

Anyone runs their own agent anywhere, registers a queue, and answers — credentials never leave their machine. Outbound-only, NAT-friendly.

📊

Live dashboard + metrics

Self-contained dashboard at /, JSON at /stats, Prometheus at /metrics — requests, tokens, latency, routing split.

🔐

Auth & mTLS

Bearer tokens (SDKs send them as the api_key) or full mutual TLS. Generate the whole trust setup with routsi certs.

Distributed by design

Let anyone plug their agent in.

Your proxy runs here; a teammate's logged-in Codex or Claude runs there. They register a queue and start answering — no inbound ports, no shared secrets.

on any machine with an agent logged in
routsi worker run --proxy https://your-proxy:8080 --queue my-agent \
  --agent 'codex exec --skip-git-repo-check -'   # reads the question on stdin, prints the answer

# now {"model":"my-agent"} routes to that worker — shows in /v1/models,
# /v1/workers (live status), and the dashboard. No worker? requests fast-fail 503.

routsi install --skills   # install the worker as an agent skill (~/.claude, ~/.codex)

Quick start

One binary. Drop a config. Point any OpenAI client at it.

01 — BUILD

Get the binary

task build          # → bin/routsi
routsi serve        # :8080
02 — CONFIG

models.yaml

default: gpt-cheap
tiers:
  cheap: gpt-cheap
  strong: gpt-strong
03 — CALL

Any OpenAI SDK

curl :8080/v1/chat/completions \
 -d '{"model":"auto",
  "messages":[{"role":"user",
   "content":"hello"}]}'
